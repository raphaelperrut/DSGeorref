# Classical profile and delivery governance foundation

This slice materializes one candidate policy and a fail-closed validator for
the ten requirements owned by `STORY-0692`. The policy records only invariants
already owned by the cited requirements, ADR-039, ADR-044, BP-001, and the
engineering operating model. It does not choose scientific thresholds.

`policy_validation.load_policy` rejects missing, extra, mistyped, or changed
controls. There is no permissive fallback. The profile keeps photometric
preparation, coordinate lineage, adaptive quota redistribution, FLANN recall
calibration, masks, priors, and the multidimensional gate explicit. The
delivery section keeps one Project item identity, required story fields, WIP,
incomplete history, and the velocity prohibition explicit.

ADR eligibility continues to use the existing
`decision_governance.validate_new_adr_eligibility` primitive. This slice only
records that independent boundary, durable impact, high reversal cost, and the
existing overlap check are mandatory; it does not create another ADR
classifier.

## Boundaries and handoff

- Contract impact: none; frozen public contracts and ADRs are unchanged.
- Persistence, HTTP, broker, migration, and live GitHub Project mutation: not
  applicable to this local foundation slice.
- Risk: this is a candidate until independent QA and Reviewer validate the
  exact commit; later EPIC-002 integration stories own repository automation.
- Rollback: revert the candidate commit. No data migration or destructive
  rollback is required.
